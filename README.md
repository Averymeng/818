# 客户广告投放诊断台 · 复盘诊断 Agent（MVP）

> 面向**广告平台商业化销售**的「客户投放经营与复盘 Agent」产品 —— 本仓库是其中 **P0「投放复盘诊断 Agent」模块的 MVP 纵向切片**（周度阶段性复盘场景）。
> 用 AIPM 框架设计：场景锚定 → 链路拆解 → 评测闭环 → 简历表达。设计底稿见 [`诊断台/AIPM_项目底稿.md`](诊断台/AIPM_项目底稿.md)。

---

## 它解决什么问题

广告平台商业化销售每周要为小红书线索投放客户做**投放复盘**：跨账户/版位/计划/素材/转化漏斗查数、定位波动、解释原因、出优化建议、做对客材料、追踪后续效果。该过程**数据量大、重复高，又需要结合客户目标做非确定性判断**——不同销售经验差异大、归因常缺证据、经验难沉淀。

诊断台把这件事产品化：**选客户 + 周期 → Agent 自动完成全层级扫描与异常下钻 → 生成有证据的结构化复盘报告 → 销售审核 → 经验回流沉淀为可复用案例**。

> 范围边界（与完整蓝图一致）：截止到**私信链路与客资成本**（曝光→笔记点击→按钮点击→私信开口→留资），**不进入**后链路（GMV/ROI/成交/有效线索）；RAG 历史案例**不替代**当前数据归因；不自动执行预算/启停等高风险操作。

## 主链路（10 节点 Agent 编排 + 8 章节报告）

```
触发(周度/主动) → 输入(周期投放数据+目标) → 预处理(完整性校验/周期对比/分层汇总)
  → 核心处理(Agent 10 节点):
      init → 数据完整性 → 全层级扫描(账户/版位/计划/素材/漏斗)
           → 分层诊断 → 异常排序(四标签:方向/形式/严重度/位置, Top3 重点)
           → LLM 下钻归因 → RAG 案例检索 → 建议生成 → 报告组装 → 事实校验
  → 输出(八章节网页报告) → 人工审核(确认/修改/驳回/信息不足) → 案例沉淀
  → 状态沉淀(案例库+Badcase) → 主动触发(日监控异常/周度任务/效果回看)
```

**八章节报告**（与产品 Schema 对齐）：封面 · 核心结论 · 指标与趋势 · 分层诊断 · 异常与原因 · 案例参考 · 优化建议 · 行动计划。

**AI 分工（代码 / 规则 / LLM / RAG / 人工）**：确定性计算与基础异常交给代码与规则；诊断规划、原因推理、案例差异判断交给 LLM 驱动的 Agent；历史经验召回交给 RAG；最终业务判断与审核留给人（商业化销售）。证据不足时输出"待验证假设/数据不足"，不强行归因。

## 技术栈

- **后端**：Python 标准库（`http.server` 自研轻量 HTTP 服务），**零第三方依赖**。
- **前端**：原生 HTML / JS / CSS，离线可降级为静态快照。
- **LLM**：单模型 DeepSeek（标准库 `urllib` 直连），可按 key 计费，无框架开销。
- **数据**：SQLite；模拟数据按日期派生种子、**可复现**（禁止临时随机），便于复测与 Badcase 定位。
- **RAG**：早期用**结构化案例库**（行业/赛道/品类/优化目标/异常签名/关键证据/动作/结果），SQL 归一化匹配召回；案例达 50–100 条后再考虑向量召回。

---

## 评测与质量保障

- **126 条自动化断言，通过 126/126**（17 个主用例 E01–E17，含拆分项）。
- 评分：MECE 分层 rubric（硬断言 + LLM-as-judge 定性），`judge_prompt` 经校准。
- 自动化：GitHub Actions CI 回归（`eval/run_eval.py`）。
- Badcase 闭环：评测发现的缺陷沉淀为回归用例，已修复 2 类召回 bug（中英签名漏匹配、AND 过严导致空召回）。
- 评测对象覆盖五类场景：正常 / 单点异常 / 复合异常 / 指标冲突 / 数据缺失。

详见 [`诊断台/eval/`](诊断台/eval) 与 [`诊断台/AIPM_项目底稿.md`](诊断台/AIPM_项目底稿.md) 的 eval 章节。

## 运行与部署

**本地运行（实时后端，可录入/生成报告）**
```bash
cd 诊断台
export DEEPSEEK_API_KEY=sk-xxx
./start.sh                      # 崩溃自重启循环，监听 0.0.0.0:8000
# 浏览器打开 http://127.0.0.1:8000
```
- macOS 常驻：用 `launchctl` 加载 `com.diag.server.plist`（RunAtLoad + KeepAlive），开机自启、崩了自动拉起，独立于会话。

**静态只读快照（他人随时查看，不能录入）**
```bash
cd 诊断台
python3 static_export.py       # 导出 web/snapshot.json
# 推送到 gh-pages 分支即可通过 GitHub Pages 访问（前端自动降级读快照）
```

```

  api_server.py        # 轻量 HTTP 服务（标准库）

    metrics.py         # 确定性指标计算
    system_prompt.md

  部署说明.md
```
