## 3. 本次修复：E14 误报（评测脚本 bug，非 Agent 缺陷）

批量首跑时 `eval_results.json` 显示 109/126，唯一未过是 **E14「报告不出现后链路结论」1/2**。定性后确认为**评测脚本误报**：

- 根因：`run_eval.py` 的 E14 报告扫描循环遍历 `artifacts/*.json`，只跳过了 `eval_results.json`，但把 `judge_calibration.json`（内含 judge 推理文本里的 ROI/GMV 字样）也当成报告来扫，触发误报。
- 修复：扫描循环改为与 E24 一致的「只扫真实报告 JSON」守卫——显式跳过 `eval_results.json` 与 `judge_calibration.json`，并对无法解析为报告（无 `chapters` 字段）的 JSON 直接跳过。
- 验证：`python3 eval/run_eval.py`（--static 复用已有 artifacts 重算断言，零成本）→ **126/126 通过**，E14 变 2/2。

> 这是评测实现口径问题，与 v1 首轮 4 个断言误报同类：**不是 Agent 缺陷，修脚本即可**。

## 4. judge 校准结论（来自 judge_calibration_report.md）

- 7 轮校准后用 3 票中位数投票启用 judge。最终分歧率 D1 17% / D2 33% / D3 33%。
- D2/D3 名义超 30% 红线，但连续 7 轮证明残余分歧**全部是 2/3 边界上的 ±1 摇摆（LLM 温度噪声）**，不是标准偏差。
- judge 对**真错误的检出率 100%**：周值/日值混淆（码上 24.28、巅峰 21.45）、下钻数字无出处（拾光/银龄）、观察清单漏项（码上）每轮都中；从未出现 1↔3 跨档错判。
- 人工基线（judge_baseline.json）按 judge 举证改判 3 处：码上 D1 3→2、码上 D3 3→2、巅峰 D3 2→3。
- **解读口径**：judge 分数看「1 分 / 跨份趋势」，单份 2/3 边界不做硬解读；如需进一步压噪声，votes 3→5（成本线性增加）。
