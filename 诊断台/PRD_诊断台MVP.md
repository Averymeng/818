## 1. 背景与机会

广告平台商业化销售需定期为客户制作投放复盘：跨账户/版位/计划/素材/转化漏斗查数、定位波动、解释原因、形成建议、制作对客材料、追踪效果。痛点（PRD §2.2）：

| 问题 | 当前表现 | 产品机会 |
|---|---|---|
| 信息分散 | 数据分层（账户/版位/计划/素材/转化） | 统一客户与周期上下文 |
| 诊断耗时 | 逐层查数、找异常、组织原因 | 系统固定扫描 + Agent 异常下钻 |
| 结论不稳定 | 经验差异大、归因缺证据 | 结论绑定指标证据，区分事实/推断/待验证 |
| 材料重复 | 每周重做网页+PPT | 统一结构化报告生成 |
| 经验流失 | 修改/执行/效果无沉淀 | 审核—行动—结果—案例回流闭环 |

## 2. 产品定位、用户与场景

### 2.1 定位
面向**广告平台商业化销售**的客户投放复盘诊断工具（MVP）。覆盖"数据 → 诊断 → 报告 → 审核 → 案例沉淀"的纵向闭环；不直接替代投手执行高风险账户操作。

### 2.2 目标用户
- **核心用户：广告平台商业化销售**——选客户与周期；审核/编辑/驳回结论；记录客户与执行反馈。
- （未来）销售管理者：查看汇总与质量结果。
- （后台）系统管理员：维护数据源/口径/模板/权限/评测。

### 2.3 核心场景（MVP 已支持）
| 场景 | 触发 | 产物 | 优先级 |
|---|---|---|---|
| 周度阶段性复盘 | 周度固定 / 销售主动发起 | 八章节结构化网页报告 + 行动建议 | P0（已落地） |
| 日常经营查看 | 按客户/周期查看数据 | 数据状态、趋势、异常提示 | P1（部分：数据查看已支持） |

### 2.4 非目标（边界，与蓝图一致）
- 不进入后链路：GMV / ROI / 成交 / 有效线索 / 回访。
- 不生成素材、不做完整 CRM、不自动调预算/启停计划。
- RAG 历史案例**不替代**当前客户数据归因。

## 3. 业务模型与口径（MVP 实现依据）

### 3.1 业务层级
**行业 → 赛道 → 客户 → 品类**（一个客户可经营多品类）。线索投放是当前转化框架，不与真实行业混层。

### 3.2 私信转化漏斗（统一口径）
**曝光 → 笔记点击 → 按钮点击 → 私信开口 → 留资**
- 优化目标为**开口**：看开口量 / 开口成本；为**留资**：看留资量 / 留资成本。
- 必须先沿漏斗**串联**定位问题环节，再**并联**拆版位/计划/笔记。

### 3.3 核心指标（确定性计算，代码承担）
CPM、CTR、CPC、按钮点击率、私信开口率、链路留资率、留资 CVR、开口成本、留资成本。

### 3.4 异常体系（四标签）
每个异常事件打：**变化方向**（正/负/中性结构）、**异常形式**（单指标/链路组合/指标冲突/结构变化/数据质量）、**严重程度**（正常/观察/异常/严重）、**发生位置**（漏斗环节 + 版位/计划/笔记）。报告重点归因 **Top 3**，排序权重：消耗影响 40% / 优化目标成本贡献 30% / 异常幅度 20% / 数据置信度 10%。

## 4. 功能需求（MVP 已实现）

### 4.1 数据进入与完整性
- 模拟数据可复现（按日期派生种子），约 51 客户 / 66 报告；手动录入（upload 源）支持销售补录。
- 数据完整性检查：缺失字段/口径冲突在诊断前显式提示；样本不足时降级分析，不强行归因。

### 4.2 Agent 诊断（10 节点编排）
`init → 数据完整性 → 全层级扫描 → 分层诊断 → 异常排序 → LLM 下钻 → RAG 案例检索 → 建议生成 → 报告组装 → 事实校验`
- **全层级扫描**：固定覆盖账户/版位/计划/素材/完整漏斗，不跳过。
- **分层诊断**：每层输出 正常/异常/数据不足 + 证据。
- **LLM 下钻**：串联漏斗定位环节 → 并联拆对象 → 提假设+证据；证据不足输出"待验证"。
- **RAG 检索**：结构化案例库召回，输出相似点 + 关键差异（写入 case_ref_log）。
- **事实校验**：结论必须引用数据，区分事实/推断/建议。

### 4.3 报告（八章节，与产品 Schema 对齐）
封面 · 核心结论 · 指标与趋势 · 分层诊断 · 异常与原因 · 案例参考 · 优化建议 · 行动计划。网页报告可展示、可审核、可保存版本与审核状态。

### 4.4 人工审核与案例沉淀
- 审核动作：确认 / 修改 / 驳回 / 信息不足，原因可追溯。
- 审核后报告沉淀为**普通参考案例**（预留执行/结果字段）；无效结论/错误归因进入 **Badcase**，用于回归评测。
- 当前案例库：21 条参考案例（结构化：行业/赛道/品类/优化目标/异常签名/关键证据/动作/结果）。

## 5. AI 能力边界（代码 / 规则 / LLM / RAG / 人工）

| 能力 | 承担者 |
|---|---|
| 指标计算与聚合 | 代码 |
| 基础异常识别（阈值/突变/缺失/目标偏离） | 代码/规则 |
| 诊断规划与原因推理 | LLM 驱动的 Agent |
| 历史经验召回 | RAG（结构化案例库，早期非向量） |
| 案例差异判断 | LLM |
| 证据校验 | 规则 + LLM 复核 |
| 最终业务判断 | 商业化销售（人工审核） |

**可靠性约束**：工具失败/数据缺失/超出轮次/证据不足时安全停止，不生成虚假确定结论。

---

## 6. 非功能要求
- **可解释性**：每条核心诊断关联数据证据；区分事实/推断/建议/待验证。
- **可复现性**：相同数据快照+配置可复现；保存 Agent 运行记录（步骤/工具调用/分支/停止条件）。
- **可评测性**：离线评测集 + CI 回归（126/126 通过）；固定模拟数据可重复运行比较版本。
- **成本可控**：单 DeepSeek 直连，记录模型/工具调用与失败重试。
- **零依赖**：标准库即可运行，无第三方包。

## 7. 验收标准（MVP）
- [x] 至少一组正常、一组异常、一组数据缺失场景端到端完成。
- [x] 账户/版位/计划/素材/转化漏斗均输出状态、证据与判断。
- [x] 证据不足时不强行归因；不执行高风险账户操作。
- [x] 结构化报告可展示、审核、保存版本、保留审核状态。
- [x] 审核修改/驳回可沉淀为案例 / Badcase。
- [x] 固定模拟数据可重复运行并比较版本（评测 126/126）。
